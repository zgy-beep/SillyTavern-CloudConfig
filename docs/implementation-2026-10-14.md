# CloudConfig 可靠性与界面改造

本次直接以当前代码为基线，保留现有 REST API、适配器和数据库历史。不以旧 README 的描述作为实现约束。

## 数据提交

`SnapshotCommitter` 统一快照提交顺序：临时文件写入并 fsync → 重命名为唯一、不可变的文件 → SQLite 事务发布版本及变更事件。SQLite 文件使用 `synchronous=FULL`，POSIX 平台在重命名后同步文件所在目录。

数据库发布失败时清理本次文件；进程在发布前退出时可能留下孤儿文件，启动及每日清理会回收超过两小时且无数据库引用的文件。此前版本路径保持可读，新文件名不覆盖旧文件。Windows 的文件系统没有同等目录 fsync 接口；这里保证应用提交顺序，不承诺存储硬件失效时的数据恢复。

强制上传在事务内重新分配版本，避免并发请求撞号。`version_sequences` 保存版本高水位，删除最新历史后也不会重用已发布的版本号。两个新表由数据库初始化自动创建，不需要手工修改已有库。

## 灾备导入

导入先检查所有记录、版本、内容类型和校验值，再准备快照文件，最后一次事务发布全部元数据。任意对象失败会撤销本次暂存文件。相同编号、不同内容的版本另建新版本，原历史文件保持不变；`import_mappings` 记录来源版本到本地版本的对应关系，重复导入保持幂等。

导出遇到无法读取的快照会明确失败，不再把缺失文件的 ZIP 当作完整备份。ZIP 解压限制为单文件 128 MiB、总计 512 MiB，防止异常归档耗尽内存。

浏览器导出是当前账号的配置版本归档。服务端定时导出包含全体账号，保存于活动数据目录的 `backups/`，滚动保留 7 份；外部镜像失败会记录任务失败，本地已生成的归档仍保留。当前导入接口把内容认领到登录账号，不执行跨账号授权恢复；全体账号归档应按原账号拆分后导入，不能当作整站数据库恢复工具。

## 权限与状态

- `/config` 对管理员和普通成员均隐藏 WebDAV 密码；普通成员额外看不到用户名、远端地址和本地镜像路径。密码输入留空会保留原值。
- 快照的类型、UID、扩展名拒绝路径分隔符、目录穿越、驱动器标识和 Windows 保留设备名；现有路径的符号链接也校验目录边界。
- 配置修改校验数值、布尔值、URL 协议及已知字段，配置文件采用临时文件加重命名保存。
- 客户端统一使用 `SHARED_READONLY`；旧订阅即使缺少模式字段，也依据来源账号保持只读。
- 列表、绑定和事件按来源账号、类型、UID 区分，同名 UID 的本人配置和共享配置分别展示。
- 变更分页只确认实际返回事件的末尾游标，并立即续取后续页；轮询避免重叠执行，切换账号后丢弃旧请求结果。
- 浏览器使用 SSE 唤醒轮询，定时轮询提供降级。自动备份跳过无内容变化的对象，避免空快照耗尽保留版本。

## 操作变化

手动推送默认检查云端版本。只有明确勾选“允许将本地旧内容设为云端最新”，才走强制上传。批量备份和自动备份只处理本人资产，遇到冲突保留待处理状态。

开启同步会读取当前账号的完整本地内容并保存于浏览器 IndexedDB，关闭时可以保留现状或恢复该备份。`/restore-local` 按原内容恢复，不使用云端拉取时的设置深度合并或聊天追加合并。清除浏览器站点数据会同时清除这些本地备份，服务端历史快照与之独立。

设置精简对磁盘读取和浏览器提交内容统一生效，排除 `oai_settings.extensions.tavern_helper` 整个分支；这包含助手变量、脚本和缓存，完整备份需要取消勾选。精简过程不修改原始本地内容。

## 界面

`listModel.js` 负责列表聚合与账号归属，`dialog.js` 负责主题加载、文本转义、弹窗焦点与通知，`theme.css` 提供隔离的样式变量。界面继承酒馆的文字、背景和强调色。

主面板包括概览、分类、搜索、内部滚动列表和固定状态栏；灾备与管理操作收进“更多工具”。共享项显示来源账号，禁用推送、分享并隐藏删除按钮。手机布局将文件来源与操作按钮分行；弹窗支持 Escape、Tab 焦点循环和关闭后焦点恢复。新增定时灾备开关和执行周期设置。

对话补全预设在面板中标为“对话预设”，有本地文件或云端快照的保留分类默认显示。分类开关为“显示空分类”；单项上传按钮统一标为“备份”。单项备份可直接点击，顶部“一键备份”处理已勾选的本人配置。

根据用户实机反馈，卡片改为独立同步勾选区、名称/状态区和文件来源/操作区。原生 checkbox 保留点击与键盘语义，独立勾选图标显示状态，固定点击范围并覆盖宿主对 checkbox 的缩放、边距和外观规则；来源文字明确左对齐，长名称自动换行，手机操作按钮独立分行。

Novel 预设、Kobold 预设、指令模板、上下文模板、系统提示词和文本生成预设移除同步入口。统一分类策略同时过滤面板、批量备份和自动备份；旧绑定不能继续上传或重新启用。服务端适配器与已有快照保留，以兼容历史归档。

本次调整通过 17 项相关回归测试，覆盖六类旧绑定的批量/自动备份排除和启用/上传拒绝。示例页叠加宿主居中与 checkbox 缩放规则，验证桌面和 390/320 像素手机宽度、明暗主题、勾选点击、空格键切换与关闭恢复弹窗；可见控件未被遮挡，面板没有横向溢出。验证使用预览数据，并非运行中的酒馆实机。

## 验证与预览

运行环境要求 **Node.js 24+**。依赖不增加原生编译模块。

```sh
npm test
npm run preview
```

预览仅监听 `127.0.0.1:13077`，使用内存中的示例配置，不连接真实酒馆、不读取账号文件。可切换明暗主题、检查手机宽度并操作主要弹窗。停止预览服务不会影响酒馆。

已有完整测试套件及新增回归已验证：文件发布失败、CAS/强制并发、版本不重用、归档校验与幂等、暂存撤销、分页无漏项、凭据脱敏、订阅只读和原始设置恢复。浏览器验证了 390×844 手机断点、1024×900 桌面断点、明暗主题、搜索、设置和上传弹窗。

2026-10-14 最终验证：Windows / Node.js v24.21.0，完整套件 **196/196 通过**，0 失败、0 跳过；执行命令 `node --test --test-concurrency=2 --test-timeout=60000 tests/unit/*.test.js tests/integration/*.test.js`。测试使用独立临时账号目录及数据库，不操作真实酒馆账号数据。

这里的浏览器验证使用预览数据；宿主酒馆的登录链路、扩展加载及各种原生刷新钩子仍需在运行中的酒馆验证。服务端 `/client` 与 `/common` 静态路径已补齐，前端仍需要通过酒馆的扩展机制加载 manifest。
